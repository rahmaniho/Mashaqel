# مشاغل (Mashaqel) — موتور ارزیابی، طبقه‌بندی مشاغل و محاسبات مزد و معوقات قانون کار ایران

موتور مستقل و مستندسازی‌شده برای سه کارکرد اصلی:

1. **ارزیابی شغل** با دو نظام مستقل:
   - **سیستم B**: نظام امتیازی چهارعاملی وزارت کار (مصوب `۱۳۸۹/۰۵/۱۸`) با ۴ عامل، ۱۴ زیرعامل و مجموع نظری `۱٬۱۳۷` امتیاز.
   - **سیستم A**: نظام ارزیابی مشاغل مصوب `۱۳۹۵/۰۳/۲۲` (شماره `۴۹۲۴۰`) با چارچوب شش‌عاملی که جزئیات کمّی آن باید از «طرح مصوب کارگاه» بارگذاری شود.
2. **طبقه‌بندی**: تطبیق امتیاز کل شغل با جدول نسخه‌بندی‌شده دامنه امتیاز گروه‌ها و تعیین **گروه پیشنهادی** با الزام تأیید کارشناس/کمیته.
3. **محاسبات مزد**: مزد شغل ۱۴۰۵، پایه سنوات گروهی، مزد مبنا، مزایای رفاهی و انگیزشی، بیمه، اضافه‌کاری/نوبت‌کاری/شب‌کاری و موتور مابه‌التفاوت و معوقات.

> تمام مبالغ در این سامانه **ریال ایران (`IRR`)** است و محافظ‌های سیستمی از اختلاط ریال/تومان جلوگیری می‌کنند.

## ۵. فرمول‌های کلیدی ۱۴۰۵ (ریال)

| فرمول | رابطه |
| :--- | :--- |
| مزد شغل روزانه | `max(round(مزد ۱۴۰۴ × 1.45 + 519,549), 5,541,850)` |
| مزد شغل ماهانه | `مزد روزانه × روزهای قابل پرداخت` (پیش‌فرض ۳۰) |
| پایه سنوات روزانه | `round(سنوات تجمیعی ۱۴۰۴ × 1.45) + نرخ پایه سنوات گروه ۱۴۰۵` |
| مزد مبنا | `مزد شغل + مزد سنوات + مزد رتبه + سایر اجزای مصوب طرح` |
| مزد جدول طرح | `Yn = b + a × (Xn − 80)` با `a_1405 = 1.45 × a_1404` و `b ≥ 5,541,850` |
| حق اولاد | `3 × 5,541,850 = 16,625,550` ریال ماهانه به ازای هر فرزند |
| اضافه‌کاری | `مزد مبنا ÷ 7.33 × 1.4 × ساعت` |
| بیمه | کارگر `7%` و کارفرما `23%` از مزد و مزایای مشمول (حق اولاد معاف) |
| معوقات | `Σ max(0, مزد استحقاقی − مزد پرداختی) × روز + Δمزایای متغیر` |

پارامترهای نسخه `1405-v2` (پس از تصویب‌نامه مسکن): بن ۲۲٬۰۰۰٬۰۰۰ — مسکن ۳۰٬۰۰۰٬۰۰۰ — تأهل ۵٬۰۰۰٬۰۰۰ — حق اولاد ۱۶٬۶۲۵٬۵۵۰ ریال ماهانه.

## ۶. محدودیت‌های آگاهانه (مطابق مستندات)

1. **زیرعامل «مسئولیت ایمنی دیگران»** در نظام ۱۳۸۹: سقف ۳۰ امتیاز مستند است اما جدول ریزسطوح رسمی در دسترس نبود؛ امتیازدهی خودکار آن غیرفعال و امتیاز کل «ناقص» علامت‌گذاری می‌شود.
2. **وزن، سطح و امتیاز نظام ۱۳۹۵** برای هر کارگاه اختصاصی است؛ بدون بارگذاری طرح مصوب (با شماره تأییدیه اداره کل روابط کار) امتیازدهی انجام نمی‌شود.
3. **پلکان مالیات بر حقوق ۱۴۰۵** ثبت نشده است؛ مالیات صفر با هشدار محاسبه می‌شود تا پس از بارگذاری قانون بودجه فعال گردد.
4. **کمک‌هزینه مسکن** در دو نسخه (`1405-v1` = ۹٬۰۰۰٬۰۰۰ و `1405-v2` = ۳۰٬۰۰۰٬۰۰۰ ریال) نگهداری می‌شود تا محاسبه مابه‌التفاوت فروردین ۱۴۰۵ ممکن باشد.
5. **گروه شغلی** بدون تأیید کارشناس و شماره صورت‌جلسه کمیته، در سطح دیتابیس (قید `CHECK`) قطعی نمی‌شود.

> بخش «شناسنامه فرمول‌ها و اسناد قانونی» بنا به درخواست کاربر **از رابط کاربری پنهان** شده است؛ داده‌های آن (۲۶ فرمول و ۱۲ سند) در موتور و در `JOB_CLASSIFICATION_FORMULAS.md` و اسنپ‌شات وب باقی مانده و حذف نشده است.

معماری: `web/engine-core.js` بازنویسی بدون وابستگی سرویس‌های موتور برای مرورگر است و `web/data/mashaqel-data.json` از دیتابیس موتور صادر می‌شود؛ `npm run verify:web` تضمین می‌کند اعداد وب‌اپ با موتور یکی باشد (۲۴۴ بررسی عددی) و `npm run test:web-ui` پوسته، مسیریابی، کارگاه‌ها، ساختار سازمانی، بانک مشاغل، کارکنان، حقوق ماهانه، معوقات، گردش‌کار تأیید کارشناسی، گزارش‌ساز، احراز هویت/نقش‌ها، پنل سرور و اعداد نمایش‌داده‌شده را با ۳۲۰ بررسی کنترل می‌کند. دو آزمون تازه هم سرور مرکزی را می‌سنجند: `npm run test:server` (۳۴ بررسی: نشست، RBAC، قفل ورود، زنجیره هش، پشتیبان، CORS) و `npm run test:web-server` (۲۶ بررسی یکپارچه پوسته وب با سرور واقعی) و `npm run check:deploy` (۴۴ بررسی بسته استقرار). هویت سازمانی هم `npm run test:sso` (۱۵ بررسی با IdP شبیه‌سازی‌شده) دارد.

### اجرای سرور مرکزی (فاز ۱۱)

```bash
npm run serve:api     # سرور روی http://localhost:8787 با SQLite داخلی Node
npm run serve:web     # وب‌اپ روی http://localhost:4173 با پراکسی /api → 8787
```

با اجرای هم‌زمان این دو، پوسته وب در نوار بالا «سرور مرکزی» را نشان می‌دهد: راه‌اندازی حساب مدیر، ورود/خروج، فهرست کاربران، گزارش فعالیت سروری، بازبینی زنجیره هش و پشتیبان مرکزی از طریق API انجام می‌شود. اگر سرور در دسترس نباشد (مثل نسخه منتشرشده روی GitHub Pages) برنامه به‌طور خودکار در «حالت محلی» فاز ۱۰ کار می‌کند.

### هویت سازمانی (فاز ۱۳)

```bash
MASHQEL_OIDC_ISSUER=https://idp.example.org/realms/org \
MASHQEL_OIDC_CLIENT_ID=mashaqel \
MASHQEL_OIDC_CLIENT_SECRET=... \
MASHQEL_OIDC_REDIRECT_URI=https://mashaqel.example.org/api/auth/sso/callback \
MASHQEL_OIDC_APP_URL=https://mashaqel.example.org/ \
MASHQEL_OIDC_ADMIN_EMAILS=boss@example.org,hr@example.org \
MASHQEL_LOCAL_LOGIN=off \
npm run serve:api
```

- دکمه «ورود با حساب سازمانی» در دروازه ورود ظاهر می‌شود؛ کاربر در نخستین ورود به‌صورت خودکار ساخته می‌شود (نقش پیش‌فرض `VIEWER` یا `EXPERT` با `MASHQEL_OIDC_DEFAULT_ROLE`، و `ADMIN` برای ایمیل‌های فهرست مدیران).
- جریان کامل استاندارد است: `GET /api/auth/sso/start` → IdP → `GET /api/auth/sso/callback` (تبادل کد با PKCE و تأیید توکن) → کد یک‌بارمصرف → `POST /api/auth/sso/exchange` → توکن نشست ۸ ساعته.
- `MASHQEL_LOCAL_LOGIN=off` ورود با رمز محلی را غیرفعال می‌کند (نصب فقط-SSO). دکمه ساخت مدیر اولیه تا وقتی کاربری وجود ندارد فعال می‌ماند تا قفل‌شدن رخ ندهد.
- آزمون خودکار با یک IdP شبیه‌سازی‌شده (Discovery، JWKS، مجوز PKCE، توکن امضاشده RS256 و حالت‌های خطا): `npm run test:sso` — ۱۵ بررسی.

### چاپ و خروجی PDF (بازبینی فاز ۱۴)

- همه دکمه‌های چاپ از مسیر مشترک `doPrint` استفاده می‌کنند: جدول‌های پهن (بانک مشاغل، ساختار سازمانی، کارکنان، حقوق، معوقات، گزارش‌ها) روی **A4 افقی** و شناسنامه شغل روی **A4 عمودی** چاپ می‌شوند؛ جهت کاغذ پس از پایان چاپ به حالت پیش‌فرض بازمی‌گردد.
- جدول‌های بلند دیگر بریده نمی‌شوند: سقف ارتفاع و اسکرول در چاپ برداشته می‌شود و سرستون‌ها در هر صفحه تکرار می‌شوند؛ ردیف‌ها بین دو صفحه شکسته نمی‌شوند.
- چاپ برگه خالی ممکن نیست: گزارش، فیش حقوقی و معوقات فقط پس از محاسبه/ساخت چاپ می‌شوند و پیام راهنما نشان داده می‌شود. صفحه ورود، نوار ابزار، فرم‌ها و پنل‌های جزئیات موقت هرگز چاپ نمی‌شوند.
- بررسی خودکار: `npm run check:print` (۴۹ بررسی) و آزمون‌های رابط کاربری چاپ در `npm run test:web-ui`.

### استقرار سازمانی (فاز ۱۲)

- بسته آماده در [`deploy/`](./deploy/README.md): `Dockerfile` (Node 22، اجرای غیرریشه، healthcheck)، `docker-compose.yml` (API + Caddy با TLS خودکار)، `nginx.conf` (TLS 1.2/1.3 + HSTS)، سرویس `systemd` با سخت‌سازی فایل‌سیستم و `.env.example`.
- **همگام‌سازی چنددستگاهی:** در حالت سرور، وضعیت سازمان نسخه‌دار ذخیره می‌شود؛ پنل تنظیمات دکمه‌های «دریافت/ارسال وضعیت» و نشان نسخه دارد و تعارض نسخه (۴۰۹) با پیام روشن گزارش می‌شود. دستگاه خالی در نخستین ورود وضعیت سرور را خودکار دریافت می‌کند.
- بررسی خودکار بسته: `npm run check:deploy`. متغیرها: `PORT`، `HOST`، `MASHQEL_DB`، `MASHQEL_CORS_ORIGIN` و `MASHQEL_API` (برای پراکسی)؛ جزئیات در [`server/README.md`](./server/README.md).

```bash
npm run export:web   # تولید web/data/mashaqel-data.json از موتور
npm run serve:web    # پیش‌نمایش محلی روی http://localhost:4173
```

**انتشار خودکار:** گردش‌کار [`.github/workflows/pages.yml`](./.github/workflows/pages.yml) با هر تغییر در `web/` یا موتور (`src/`, `sql/`) روی شاخه `main` اجرا می‌شود، داده‌ها را از موتور بازتولید می‌کند، آزمون‌های موتور، تطبیق عددی و آزمون دودی رابط کاربری را می‌گذراند و سپس پوشه `web/` را روی GitHub Pages منتشر می‌کند.

آدرس انتشار: **<https://rahmaniho.github.io/Mashaqel/>**
